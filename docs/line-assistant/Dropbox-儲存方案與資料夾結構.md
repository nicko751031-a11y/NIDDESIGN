# Dropbox 儲存方案與資料夾結構

文件版本：2026-08-22
適用：川果設計 NID DESIGN LAB｜LINE 助理系統第一步

---

## 1. 為什麼是 Dropbox

### 1.1 決策理由

對室內設計公司來說，雲端儲存的選擇不是比容量單價，而是比**同仁能不能像用本機資料夾一樣用它**。三個關鍵情境：

**情境一：AutoCAD 開 DWG**
設計圖普遍使用外部參照（xref）——平面圖參照到軸線圖、家具圖參照到平面圖。xref 記的是檔案路徑。只有「本機同步資料夾」能讓 AutoCAD 正常解析；任何需要先下載的儲存服務，開圖就會一路跳缺少參照。

**情境二：找三個月前的報價單**
同仁的習慣是開檔案總管往下點，不是登入網頁後台搜尋。放在 Dropbox 同步資料夾就是原生體驗。

**情境三：業主臨時要一份圖**
Dropbox 可以對單一檔案或資料夾產生分享連結，不用把整個空間開放。本系統會自動為每個檔案建立分享連結並寫進 Notion。

### 1.2 與其他選項的比較

| 面向 | Dropbox | Google Drive | Cloudflare R2（現行） |
|---|---|---|---|
| DWG + xref 可用性 | ✅ 最佳 | 🟡 Drive for Desktop 可用，路徑較易斷 | ❌ |
| 大檔同步 | ✅ 區塊級差異同步，最穩 | 🟡 | ❌ 非同步服務 |
| 選擇性同步 | ✅ Smart Sync 成熟 | 🟡 | — |
| 版本還原 | ✅ 180 天 | ✅ 30 天 | ❌ 需自建 |
| 檔案總管操作 | ✅ | ✅ | ❌ |
| 每月成本（3 人） | 約 NT$1,300–1,500 | 若已有 Workspace 則近乎 0 | 極低（約 NT$50） |
| n8n 整合難度 | 低 | 低 | 中 |

**R2 便宜但實務上會被放棄使用**——同仁無法用檔案總管操作，每次都要下載，久了就沒人用，歸檔系統也就失去意義。

**如果公司已經在用 Google Workspace**，Drive 是合理的省錢選項，代價是 DWG 外部參照較不穩定。要換的話，工作流只需替換 `Dropbox｜上傳檔案` 與 `Dropbox｜建立分享連結` 兩個節點。

### 1.3 方案建議

| 階段 | 方案 | 月費（約） | 說明 |
|---|---|---|---|
| 第一步驗證（1–2 個月） | Dropbox **Plus** 個人版 2TB | NT$330 | 先跑通流程、累積實際用量資料 |
| 正式上線 | Dropbox **Business Standard** | NT$1,300–1,500 | 3 人起、5TB、團隊資料夾、管理主控台、180 天版本還原 |
| 資料量超過 5TB | Business **Advanced** | 依報價 | 空間依需求擴充 |

> 建議先用 Plus 跑一個月。看實際每月增加多少 GB，再決定升級時機——影片是最大的變數，一段現場影片動輒 100MB 以上。

## 2. 資料夾結構

### 2.1 路徑規則

```text
/NIDDESIGN-LINE助理/
  └─ {群組名稱}_{GroupID後6碼}/
       └─ {YYYY-MM}/
            └─ {YYYYMMDD-HHMMSS}_{發送者}_{原始檔名}.{副檔名}
```

實例：

```text
/NIDDESIGN-LINE助理/
  ├─ 文心南六路｜工程群_56a1b2/
  │    ├─ 2026-07/
  │    │    ├─ 20260715-091203_陳小明_現場拆除進度.jpg
  │    │    └─ 20260718-143055_李師傅_水電配置圖.dwg
  │    └─ 2026-08/
  │         ├─ 20260803-101533_王設計_文心南六路_廚具報價單_v2.pdf
  │         └─ 20260812-165502_陳小明_泥作缺失.mp4
  ├─ 文心南六路｜業主群_8c4d1e/
  │    └─ 2026-08/
  └─ 內部討論_3f9a70/
       └─ 2026-08/
```

### 2.2 為什麼這樣分

| 設計 | 理由 |
|---|---|
| 群組名稱後面接 **GroupID 後 6 碼** | 同一個案子常有「業主群」「工程群」同名情況；接上 ID 才不會互相覆蓋。群組在 LINE 改名後也還能靠 ID 對應 |
| 中間分 **年-月** | 一個施工中的群組每月可能上傳上百張照片，不分月會難以瀏覽 |
| 檔名前綴 **時間戳** | 讓檔案總管依名稱排序＝依時間排序，不必依賴修改時間（同步後會變動） |
| 檔名含 **發送者** | 追溯來源不必回頭翻 LINE |
| 保留 **原始檔名** | 報價單、圖號等資訊都在原檔名裡，不能丟 |
| 同名不覆蓋（`autorename`） | 同一天上傳兩份同名檔會自動變成 `xxx (1).pdf`，不會蓋掉先前的 |

### 2.3 檔案類型與用途分類

上傳時系統會自動判斷兩個欄位並寫進 Notion「05｜檔案索引」：

**檔案類型**（依副檔名）

| 分類 | 副檔名 |
|---|---|
| 照片 | jpg, jpeg, png, gif, webp, heic, heif, bmp, tif, tiff |
| 影片 | mp4, mov, avi, mkv, m4v, 3gp, wmv |
| 音訊 | m4a, mp3, wav, aac, ogg, amr |
| PDF | pdf |
| CAD 圖檔 | dwg, dxf, dwf, rvt, rfa, skp, 3ds, max, sat, step, stp, igs, iges |
| 試算表 | xls, xlsx, xlsm, csv, numbers |
| 文件 | doc, docx, ppt, pptx, txt, rtf, pages, key, odt |
| 壓縮檔 | zip, rar, 7z, tar, gz |
| 其他 | 以上皆非 |

**用途分類**（依檔名關鍵字，猜不到就是「待分類」）

| 分類 | 觸發關鍵字 |
|---|---|
| 報價單 | 報價、估價、quote、quotation |
| 合約 | 合約、契約、contract、訂單 |
| 設計圖 | 所有 CAD 圖檔，或檔名含 平面、立面、剖面、施工圖、圖說、大樣 |
| 完工照 | 完工、驗收、交屋 |
| 材料樣品 | 材料、樣品、sample、建材 |
| 施工照片 | 現場、施工、進度、缺失 |
| 待分類 | 以上皆非 |

> **實務建議**：請同仁養成在檔名裡寫清楚用途的習慣，例如
> `文心南六路_廚具報價單_v2.pdf`、`A-01_一樓平面配置圖.dwg`。
> 自動分類的準確度幾乎完全取決於檔名品質，而好檔名對人找檔案也一樣有用。

## 3. 使用注意事項

### 3.1 照片會被壓縮（重要）

LINE 傳送「照片」時會自動壓縮並移除 EXIF。透過本系統備份的也是壓縮後的版本。

**要保留原檔（原始解析度、拍攝時間、GPS）時，請用「檔案」方式傳送**：

- iPhone：聊天室 `+` → 檔案 → 瀏覽 → 選照片
- Android：聊天室 `+` → 檔案 → 選照片

工作流的畫布上也有便利貼提醒這件事。建議在群組公告一次。

### 3.2 檔案大小上限

| 限制 | 數值 | 超過時 |
|---|---|---|
| LINE 傳送上限 | 1GB | LINE 端就會擋下 |
| 本系統單次上傳 | **150MB** | Notion「05｜檔案索引」會標成「上傳失敗」，需人工補傳 |

長影片建議直接放進 Dropbox 共享資料夾，再把連結貼進 LINE。

### 3.3 檔案下載期限

LINE 的檔案內容有保存期限，過期後無法再取得。也就是說：**如果 Webhook 漏接了某則附件訊息，之後無法補救**。

對策：

- LINE Console 已開啟 Webhook redelivery
- 已設定錯誤通知，n8n 失敗時會 LINE 推播給管理者
- 每天看一次「05｜檔案索引」的「備份狀態」欄位，非「已備份」的要人工處理

## 4. 團隊設定建議

### 4.1 資料夾權限

在 Dropbox Business 主控台：

1. 把 `/NIDDESIGN-LINE助理/` 設為**團隊資料夾**
2. 全體同仁給「可編輯」或「僅檢視」
3. 含業主的群組資料夾若有敏感內容，可個別調整權限

### 4.2 同步設定

建議所有同仁在 Dropbox 桌面版開啟**選擇性同步**：

- 只同步目前在跑的專案群組資料夾
- 已結案的專案改成「僅線上」，不佔本機硬碟

這樣才能兼顧 DWG 直接開啟與硬碟空間。

### 4.3 保留政策

| 資料 | 建議保留期 | 說明 |
|---|---|---|
| 設計圖（DWG／PDF） | 永久 | 保固期後仍可能需要 |
| 報價單、合約 | 永久 | 法定與商業需求 |
| 施工照片 | 結案後 5 年 | 保固爭議舉證用 |
| 影片 | 結案後 2 年 | 佔空間最大，最先清 |
| 貼圖、閒聊截圖 | 不備份 | 系統不下載貼圖 |

清理時請同步刪除 Notion「05｜檔案索引」對應的列，否則會留下失效連結。

## 5. 若要改用其他儲存服務

工作流只有兩個節點跟 Dropbox 綁定：

| 節點 | 作用 |
|---|---|
| `Dropbox｜上傳檔案` | POST `https://content.dropboxapi.com/2/files/upload` |
| `Dropbox｜建立分享連結` | POST `https://api.dropboxapi.com/2/sharing/create_shared_link_with_settings` |

換成 Google Drive、OneDrive 或 S3／R2，只要替換這兩個節點，並讓「組出檔案索引」節點的 `upload.path_display`、`upload.name`、`upload.size`、`share.url` 對應到新服務的回傳欄位即可。路徑規則（`組出 Dropbox 路徑` 節點）可以完全沿用。
