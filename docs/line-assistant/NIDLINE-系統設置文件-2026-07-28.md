## 1. 系統目標

此系統讓「川果設計 NID DESIGN LAB」LINE 官方帳號加入公司 LINE 群組後，自動在背景執行：

- 保存群組文字訊息
- 從文字中辨識工作、聯絡事項、行事曆、決策及一般資訊
- 保存 LINE 群組內的圖片、影片、音訊及檔案
- 提供管理儀表板
- 提供工作事項管理 API
- 產生可訂閱的 iCalendar 行事曆

目前機器人採「背景記錄模式」，收到訊息後不會在 LINE 群組內自動回覆。

- `niddesignlab.com` 主網站繼續使用 WordPress。

## 6. 資料庫結構

### `messages`

保存每一筆 LINE 群組訊息及原始事件。

主要欄位：

- `id`：LINE Message ID
- `group_id`：LINE Group ID
- `user_id`：傳送者 LINE User ID
- `display_name`：群組顯示名稱
- `message_type`：text、image、video、audio、file 等
- `text`：文字內容
- `sent_at`：LINE 事件時間
- `raw_json`：原始 LINE Webhook JSON

### `items`

保存從文字訊息整理出的工作資訊。

分類：

- `task`：工作事項
- `contact`：聯絡事項
- `calendar`：行事曆／會議
- `decision`：決策
- `info`：一般資訊

主要欄位：

- 標題、詳細說明、負責人
- 到期時間
- 優先級：low、normal、high、urgent
- 狀態：open、done、cancelled 等
- AI 判斷信心值

### `attachments`

保存附件索引及 R2 儲存位置。

主要欄位：

- LINE Message ID
- 群組、傳送者及顯示名稱
- 檔名、內容類型、檔案大小
- R2 Storage Key
- 傳送時間及保存狀態

R2 目錄格式：

```text
groups/{LINE_GROUP_ID}/{YYYY-MM-DD}/{MESSAGE_ID}-{FILE_NAME}
```

## 7. 附件備份範圍

目前自動備份：

- 圖片 `image`
- 影片 `video`
- 音訊 `audio`
- 一般檔案 `file`

備份流程：

1. Webhook 收到附件事件。
2. 使用 Channel Access Token 向 LINE 下載內容。
3. 將內容寫入 R2 `FILES`。
4. 將檔名、大小、類型及儲存位置寫入 `attachments`。

限制：

- 系統必須在 LINE 允許下載的期限內處理附件。
- LINE 未成功投遞 Webhook 時，系統無法知道該附件存在，也無法備份。
- 貼圖、位置、Flex Message 等目前只會依訊息事件狀況保存基本紀錄，不屬於檔案備份範圍。

## 8. API 與行事曆

### 儀表板摘要

```http
GET /api/dashboard
Authorization: Bearer {ADMIN_TOKEN}
```

回傳：

- 各狀態工作數量
- 近期或高優先工作
- 最近訊息
- 最近檔案
- 檔案總數
- 行事曆網址

### 工作項目

```http
GET /api/items
Authorization: Bearer {ADMIN_TOKEN}
```

```http
POST /api/items
Authorization: Bearer {ADMIN_TOKEN}
Content-Type: application/json
```

新增資料可包含：

- `category`
- `title`
- `details`
- `owner`
- `due_at`
- `priority`
- `status`
- `group_id`

單筆項目的更新及操作路由位於：

```text
/api/items/{id}
```

### 檔案

```http
GET /api/files
Authorization: Bearer {ADMIN_TOKEN}
```

單筆檔案存取路由：

```text
/api/files/{id}
```

### iCalendar

```text
https://line.niddesignlab.com/calendar.ics?token={ADMIN_TOKEN}
```

行事曆只輸出：

- 有 `due_at` 的項目
- 狀態不是 `done` 或 `cancelled` 的項目

請勿公開包含 Token 的完整行事曆網址。

## 9. 管理與安全機制

- LINE Webhook 使用 `X-Line-Signature` 和 Channel Secret 驗證。
- 簽章錯誤會回傳 HTTP `401 invalid_signature`。
- 管理 API 使用 `Authorization: Bearer {ADMIN_TOKEN}`。
- 行事曆使用 URL 查詢參數 `token`。
- 密鑰不存入公開網站程式碼或本文件。
- 公開站可能遭自動掃描 `.env`、`wp-config.php`、備份檔等敏感路徑；目前這些路徑皆回傳 `404`。
- `webhook.site` 目前不是正式 Webhook 目的地，只可作臨時除錯工具。

1. 建立一個新的普通 LINE 群組。

5. 上傳一張測試圖片或測試檔案。

   - 附件清單出現測試檔案

注意：機器人正常情況下也不會在群組回話；應以儀表板、資料庫及伺服器 Webhook 紀錄判斷是否成功。

## 11. 故障排查順序

### 群組傳訊息但儀表板沒有資料

依序檢查：

1. LINE 官方服務是否正常：  
   https://api.line-status.info/
2. LINE Developers 的 Use webhook 是否啟用。
3. Webhook URL 是否仍為：  
   `https://line.niddesignlab.com/webhook/line`
4. Verify 是否成功。
5. 官方帳號是否真的在該群組中。
6. 是否使用正確的官方帳號 `@549mpmon`。
7. 正式站是否收到 `POST /webhook/line`。
8. 若有 POST，檢查 HTTP 狀態：

   - `200`：Webhook 已接受
   - `401`：Channel Secret 或簽章驗證有問題
   - `500`：程式、資料庫、OpenAI 或檔案下載處理失敗

### 文字有保存但沒有分類

檢查：

- `OPENAI_API_KEY` 是否有效
- `OPENAI_MODEL` 是否可用
- OpenAI API 是否有配額或服務異常
- 文字是否包含可辨識的工作／聯絡／日期資訊

### 附件沒有備份

檢查：

- `LINE_CHANNEL_ACCESS_TOKEN` 是否有效
- R2 `FILES` 是否正常綁定
- LINE 內容下載 API 的回應狀態
- 檔案事件是否在有效下載期限內處理
